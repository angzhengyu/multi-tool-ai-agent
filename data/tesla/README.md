# 特斯拉财务数据（官方一手 · 真实业务表）

**来源：SEC EDGAR 官方 XBRL 接口**（`data.sec.gov`，特斯拉 CIK `0001318605`）。
由 `fetch_tesla_sec.py` 抓取，**可重复再生**（纯标准库，不需要装任何库）。

| 文件 | 形状 | 用途 |
|---|---|---|
| `tesla_financials.csv` | 11 行 × 7 列 | **宽表**：年份 × 6 指标（营收 / 毛利 / 营业利润 / 净利润 / 研发费用 / 销售及管理费用），单位**百万美元** |
| `sec_raw_facts.csv` | 66 行 × 6 列 | **原始取数痕迹**：年份 / 指标 / tag / 原始美元 / 来自哪份申报 / 申报日。用于对账复查，也是"长表"形态 |

## ⚠️ 曾经有过一次数据冲突（已清理，留作教训）

早期本项目里还放着三张**演示表**（`tesla_income_long.csv` / `_wide.csv` / `_dirty.csv`），
数字取自另一份二手来源。它们和官方数据**对不上**：

| 指标 | 二手来源（已删） | **官方 SEC** |
|---|---|---|
| 2014 毛利 | 352 | **881.7** |
| 2014 毛利率 | 11.0% | **27.57%** |
| 2024 毛利 | 14,769 | **17,450** |
| 2024 研发费用 | 4,045 | **4,540** |

Agent 当时**自己发现并报告了这个冲突**（"同一个 2014 年有两套互相打架的数字"）——
说明它的交叉核对是有效的；但两份数据本就不该同时在库里。**三张演示表已删除。**

> 教训：**数据只能有一个真相来源。** 抄来的数字一旦和官方混放，
> 后面所有分析都会在"用哪份"上赌运气。

## 抓取时挡掉的两个 XBRL 真坑（都写在 `fetch_tesla_sec.py` 注释里）

1. **同一概念换 tag**：营收只用新 tag（`RevenueFromContractWithCustomerExcludingAssessedTax`）
   只能取到 5 年（2018 才开始申报）→ 必须**跨候选 tag 按年份合并补齐**，才能凑满 11 年。
2. **一份 10-K 里同时申报年度值与季度值**：只按 `form=10-K & fp=FY` 筛会捞到季度数，
   早年数字会莫名变小 → 必须校验 `start → end` 跨度确实是**整年**（350~380 天）。
